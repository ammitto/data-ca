= Ammitto Canadian sanctions data

image:https://github.com/ammitto/data-ca/actions/workflows/fetch.yml/badge.svg["Fetch Data", link="https://github.com/ammitto/data-ca/actions/workflows/fetch.yml"]

This repository stores the Consolidated Canadian Autonomous Sanctions List
as YAML for Ammitto. Global Affairs Canada publishes the source list;
`processed/` holds one file per listing.

== Source

* Publisher: Global Affairs Canada
* List page: https://www.international.gc.ca/world-monde/international_relations-relations_internationales/sanctions/consolidated-consolide.aspx?lang=eng
* File downloaded (XML): https://www.international.gc.ca/world-monde/assets/office_docs/international_relations-relations_internationales/sanctions/sema-lmes.xml

The list includes individuals and entities subject to sanctions regulations
made under the Special Economic Measures Act (SEMA) and the Justice for Victims
of Corrupt Foreign Officials Act (JVCFOA). Global Affairs Canada notes that
which provisions apply to a listing is set by the regulations it appears in.

== Contents

`processed/` holds one file per listing, named after the regulations, schedule
and item number: `processed/ca-Belarus-B-larus-1-Part-1-100.yaml` is item 100
of schedule 1, part 1 of the Belarus regulations.

`processed/_index.yaml` lists every file, with the time of the last fetch.

Each field is present only when the list gives a value.

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `country` | string | The regulations the listing falls under, as published, usually a country in English and French (`Russia / Russie`), sometimes a theme (`Hamas Terrorist Attacks / Attaques terroristes du Hamas`) or the JVCFOA regulations
| `last_name` | string | Individuals: family name
| `given_name` | string | Individuals: given names
| `entity_or_ship` | string | Entities and ships: the name
| `date_of_birth_or_ship_build_date` | string | Date of birth of an individual, or build date of a ship
| `schedule` | string | Schedule and part of the regulations, such as `1, Part 1`
| `item` | string | Item number within that schedule
| `date_of_listing` | string | Date the listing was made, `YYYY-MM-DD`
|===

Values are kept as published, including stray spaces, tabs and line breaks;
trim them before comparing names.

`downloaded/` is empty.

== Using the data

Clone or download this repository and run either example from its root
directory.

Ruby:

[source,ruby]
----
require "yaml"

Dir.glob("processed/ca-*.yaml").sort.each do |path|
  record = YAML.safe_load_file(path)
  name = record["entity_or_ship"] ||
         [record["given_name"], record["last_name"]].compact.join(" ")
  name = name.gsub(/[[:space:]]+/, " ").strip
  puts [record["country"], record["item"], name].join("\t")
end
----

Python (requires PyYAML, installed with `python3 -m pip install PyYAML`):

[source,python]
----
import glob
import yaml

for path in sorted(glob.glob("processed/ca-*.yaml")):
    with open(path, encoding="utf-8") as f:
        record = yaml.safe_load(f)
    name = record.get("entity_or_ship") or " ".join(
        part for part in (record.get("given_name"), record.get("last_name")) if part
    )
    name = " ".join(name.split())
    print(record["country"], record["item"], name, sep="\t")
----

The same list, harmonized with the other sources into JSON-LD:
https://www.ammitto.org/api/v1/sources/ca.jsonld

== Harmonized field mapping

The https://github.com/ammitto/ammitto/blob/main/lib/ammitto/sources/ca/transformer.rb[ca transformer]
maps the processed source fields below to canonical Ruby attributes.
Entity classes are in `Ammitto::Ontology::Entities`, entry/regime classes in
`Ammitto::Ontology::Sanction`, and nested values in
`Ammitto::Ontology::ValueObjects`. JSON-LD serialization can use different keys.

[cols="2,2,4",options="header"]
|===
| Source fields | Canonical target | Transformation

| `country`, `schedule`, `item`
| `Entity.id`, `SanctionEntry.id`, `entity_id`, `reference_number`
| Join the source fields into a sanitized local reference, then build source-scoped IDs.

| `given_name`, `last_name`, `entity_or_ship`, `ship_imo_number`
| Concrete entity class
| Personal names select `PersonEntity`; otherwise a recognized IMO selects `VesselEntity`, with `OrganizationEntity` as fallback.

| `given_name`, `last_name`, `entity_or_ship`, `aliases`
| `Entity.names` (`NameVariant`)
| Build a primary name from personal names or the entity/ship name; split aliases on semicolons and deduplicate them.

| `date_of_birth_or_ship_build_date`
| `PersonEntity.birth_info` (`BirthInfo`) or `VesselEntity.build_year`
| Preserve readable birth dates/years and circa; alternative dates joined by "or" remain in source YAML. A vessel build year requires four digits.

| `ship_imo_number`, `title_or_ship_type`
| `VesselEntity.imo_number`, `vessel_type`; `PersonEntity.title`
| Read the IMO and use the English part of the bilingual title/type value.

| `country`
| `SanctionEntry.regime` (`SanctionRegime`)
| Apply the configured programme lookup or use a `CA_` code derived from the source text.

| `schedule`, `item`, `date_of_listing`
| `Entity.remarks`, `SanctionEntry.remarks`, `raw_source_detail.source_specific_fields`
| Listing date remains in entity remarks and `ca:date_of_listing` metadata; the transformer does not create a period from it.

| Source-wide transformer defaults
| `SanctionEntry.status`, `effects` (`SanctionEffect`)
| Set active status and a full-scope asset-freeze effect.

|===

== Updates

The `Fetch Data` workflow (`.github/workflows/fetch.yml`) downloads the list
every day at 07:30 UTC and commits any change to `processed/`. It runs with
`--prune`, so a listing Canada has removed is deleted here on the next fetch.

== Development

`processed/` is generated by the Ammitto gem. To refresh it locally, use
Ruby 3.3 (the version selected by the fetch workflow) and Bundler. From
the repository root, run:

[source,shell]
----
bundle install
bundle exec ammitto fetch ca --format yaml --output-dir processed --verbose --prune
----

`--prune` removes files for listings no longer present in the fetched list.
Review the generated changes before committing them.

Fetch and parser changes belong in the
https://github.com/ammitto/ammitto[Ammitto gem]; its source models are in
https://github.com/ammitto/ammitto/tree/main/lib/ammitto/sources/ca[`lib/ammitto/sources/ca/`].
Report data or source-list issues in
https://github.com/ammitto/data-ca/issues[this repository].
